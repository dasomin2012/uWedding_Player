## 2. O6-A — qt 자동 폴백 (메인 작업)

### 2.1 문제 정의

현재 `ObsProcessManager::State::Failed` 진입 시 `src/app/Application.cpp:114-119`에서 다음만 수행:

```cpp
connect(m_obsProc.get(), &ObsProcessManager::failed, this,
        [this](const QString& r) {
            qCritical() << "OBS failed:" << r;
            m_controlWindow->setStatusText(tr("OBS failed: %1").arg(r));
        });
```

→ 상태바 메시지만 표시. **Live 송출은 사실상 중단**. 본식 진행 중 OBS가 재기동 한계(6회)를 초과해 `Failed`로 떨어지면 식이 멈춘다.

### 2.2 목표 (수용 기준 = Acceptance Criteria)

1. `engine=obs`로 기동 후 `ObsProcessManager`가 `Failed` 상태로 진입하면, **자동으로 qt 백엔드(`LiveWindow` + libVLC)로 sink를 교체**하고 즉시 `LiveWindow::showOnMonitor(outputMonitorIndex)` 호출.
2. 폴백 발생 시점에 **현재 Preview의 `SceneModel`을 그대로 다시 take**해서 Live가 검정 화면이 되지 않도록 함(이상적 — best-effort 수용).
3. 폴백 후 `TakeController::take()` 가 새 sink(qt)로 정상 동작.
4. 상태바에 `"OBS 실패 — qt 백엔드로 폴백됨"` 메시지 표시.
5. 폴백 후 `m_obsBackend`/`m_obsProc`의 소멸 순서가 안전한지(역순 소멸 규칙) 보장. **추가 UAF 시나리오를 만들지 말 것.**
6. 정상(qt만, OBS 미사용) 경로는 동작 무변경.
7. 빌드 통과: `cmake --build build --config Release` 무경고/무에러.

### 2.3 필요한 소스 변경 (최소 변경 원칙)

#### a) `src/take/TakeController.{h,cpp}` — sink 교체 API 추가

현재 `m_live`는 생성자 인자로 받아 변경 불가. 런타임 교체용 setter 추가.

```cpp
// TakeController.h (public 구역)
void setSink(ILiveSink* live);  // 폴백 등 런타임 sink 교체용
```

```cpp
// TakeController.cpp
void TakeController::setSink(ILiveSink* live) {
    m_live = live;
    // 새 sink에 현재 전환 모드/캔버스 등 동기화는 호출 측 책임
    // (Application::installFallback 에서 명시적으로 setTransition·setCanvasSize 재호출)
}
```

#### b) `src/app/Application.{h,cpp}` — 폴백 핸들러 추가

**Application.h** — private 메서드 선언:

```cpp
#if defined(UWP_HAS_OBS)
    void installQtFallback(const QString& reason);  // O6-A: OBS Failed 시 qt로 교체
#endif
```

**Application.cpp** — `Failed` 시그널에서 호출. 기존 `failed` 람다를 다음과 같이 교체:

```cpp
connect(m_obsProc.get(), &ObsProcessManager::failed, this,
        [this](const QString& r) {
            qCritical() << "OBS failed — falling back to qt:" << r;
            installQtFallback(r);
        });
```

새 메서드 본체:

```cpp
#if defined(UWP_HAS_OBS)
void Application::installQtFallback(const QString& reason) {
    // 1) TakeController가 OBS 백엔드를 참조하지 못하게 즉시 단절
    if (m_takeController) {
        m_takeController->setSink(m_liveWindow.get());
    }

    // 2) 새 sink(qt)에 캔버스/전환 모드 재주입
    m_liveWindow->setCanvasSize(m_settings.canvasWidth(),
                                m_settings.canvasHeight());
    const auto mode = (m_settings.takeDefaultMode().toLower() == "cut")
        ? TransitionEffect::Mode::Cut
        : TransitionEffect::Mode::Fade;
    if (m_takeController) m_takeController->setMode(mode);

    // 3) LiveWindow 표시 (OBS 경로에서 숨겨져 있던 상태)
    m_liveWindow->showOnMonitor(m_settings.outputMonitorIndex());

    // 4) 현재 Preview를 즉시 다시 take (Live 검정 회피 — best-effort)
    if (m_takeController) m_takeController->take();

    // 5) OBS 리소스 정리는 "다음 이벤트 루프 턴"에 (현재 람다 컨텍스트가
    //    obsProc 시그널 위에서 실행 중이므로 즉시 reset 금지)
    QMetaObject::invokeMethod(this, [this]() {
        // 멤버 순서 역순 소멸 규칙에 맞춰 backend 먼저, proc 나중
        m_obsBackend.reset();
        m_obsProc.reset();
    }, Qt::QueuedConnection);

    // 6) UI 안내
    m_controlWindow->setStatusText(
        tr("OBS 실패 — qt 백엔드로 폴백됨: %1").arg(reason));
    qInfo() << "Application: qt fallback installed — reason:" << reason;
}
#endif
```

**핵심 안전성 주의:**
- `m_obsBackend.reset()`/`m_obsProc.reset()`을 **이 람다 내부에서 즉시 호출 금지**. 람다는 `m_obsProc`의 `failed` 시그널 emit 컨텍스트 위에 있으며, 즉시 소멸시키면 시그널 emit 중 객체 파괴로 크래시. `Qt::QueuedConnection`으로 다음 이벤트 루프 턴에 처리.
- `ObsClient` 소멸자에 이미 `blockSignals(true) + abort()` 방어가 있지만(`src/obs/ObsClient.cpp:29-36`), Queued 소멸로 추가 안전 마진 확보.

### 2.4 작업 순서 (Claude Code 권장 절차)

1. **현 상태 확인**: `src/app/Application.cpp:96-124`, `src/app/Application.h:52-57`, `src/take/TakeController.{h,cpp}` 정독.
2. **TakeController에 `setSink()` 추가** (위 §2.3-a).
3. **Application에 `installQtFallback()` 추가** (위 §2.3-b), `failed` 람다 교체.
4. **빌드**: `cmake --build build --config Release` (Windows 환경에서, 본 샌드박스 아님).
5. **로컬 검증 시나리오** (사용자 측 수동, 본 샌드박스 불가):
   - `engine=obs`로 기동 → OBS가 뜬 뒤 작업관리자에서 `obs64.exe` 강제종료.
   - `ObsProcessManager`가 재기동 6회 시도 후 `Failed` 진입.
   - 로그에서 `Application: qt fallback installed` 확인.
   - LiveWindow가 확장 모니터에 표시되고, Take 버튼이 qt로 동작하는지 확인.
6. **로그 검증**: `build/Release/data/uWeddingPlayer.log` — `qt fallback installed`, sink 교체 후의 `Take: N layer(s) → Live` 메시지.

### 2.5 비-목표 (이 핸드오프 범위 밖)

- OBS 재기동 정책 변경 (재기동 한계 6회 유지).
- 폴백 **이후 OBS 재투입**(qt → obs 복귀) — 별도 작업.
- NovaStar presetId 호출 — O5에서 처리.
- LicenseS/NOTICE — O6-B에서 처리.

### 2.6 리스크 & 결정 필요 사항

1. **폴백 시 sink 교체와 다음 Take 사이의 경합**: `installQtFallback`에서 `setSink()` 직후 `take()`를 부르는데, qt sink의 transition이 아직 없는 첫 호출에서 dip-to-black 애니메이션이 튈 수 있음. → 본식 안전성 관점에서 "검정으로 튀는 것보다 한 번 깜빡이는 것이 낫다". 사용자 의견 다르면 폴백 시 `Cut` 강제 모드로 조정.
2. **OBS가 모니터를 잡고 있던 상태의 잔존**: OBS 프로세스 종료 시 OBS가 잡고 있던 fullscreen projector가 즉시 해제되지 않으면 LiveWindow `showOnMonitor`가 같은 모니터를 잡는 데 실패할 수 있음. 검증 시 1차 관찰 필요. 실패 시 `QTimer::singleShot(500ms, ...)`로 지연 시도.
3. **GPL 경계 재확인**: 본 작업은 `src/obs/*` 코드를 건드리지 않음. `src/app/Application.cpp`만 변경. **libobs 헤더/심볼 의존 0 유지**.

## 4. Claude Code에게 — 작업 시 지켜야 할 규칙

1. **GPL 격리는 절대선**: `src/obs/*` 와 그 의존이 `libobs` 헤더/심볼/링크를 끌어오는지 매 변경마다 자문. 의심되면 작업 중단 후 PM(사용자)에게 확인.
2. **코딩 컨벤션**: CLAUDE.md §"Coding Conventions" 준수. `m_` 접두사, PascalCase 클래스, Qt new connect syntax, `#pragma once`.
3. **메모리/소멸 순서**: `Application` 멤버 선언 순서(`m_obsBackend` → `m_obsProc`)는 의도된 역순 소멸. **건드리지 말 것**. 새 멤버 추가 시 주석으로 의도 명시.
4. **샌드박스 한계**: 본 환경은 Linux 샌드박스 + git 워크트리 → `git log`/Windows 빌드 직접 실행 불가. **빌드/실행 검증은 사용자(Windows)가 담당**.
5. **커밋 단위**: O6-A는 1개 커밋(또는 TakeController/Application 2개 커밋)으로 묶음. 메시지는 "O6-A: qt fallback on OBS Failed". 푸시는 사용자 명시 요청 시에만.
6. **불확실하면 멈춤**: 본 핸드오프와 코드가 충돌하면(예: 보고서가 가리키는 라인 번호가 안 맞음) 임의 추정 금지. 사용자에게 보고 후 진행.
